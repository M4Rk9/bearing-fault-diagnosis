# Parallel 1D-CNN + LSTM with STFT, DWT and Envelope

This is an additive experiment. The original CNN and its feature export are unchanged.

## Dataset

Download and extract the supplied [Drive folder](https://drive.google.com/drive/folders/1qR96FcLrIDfTck5qRwqEBCpYKuxXntJG) into `data/raw/envelope` so that the following paths exist:

    data/raw/envelope/
      train_70/
        Healthy/
          index.csv
          Clean/signal.npy
          Clean/envelope_frames.npy
          Noisy/signal.npy
          Noisy/envelope_frames.npy
        Inner_Race_IR/
        Ball_BR/
        Outer_Race_OR_IO/
      test_30/
        ... same four folders and files ...

Keep the original raw MAT files under `Datasets/RAW/CWRU Dataset`. The other Drive arrays are optional for this experiment. Do not concatenate the existing GitHub feature export and Drive features by array row number: the Drive windows include a different Healthy hop and boundary exclusions. The script verifies every clean Drive window against the manifest-pinned GitHub MAT files, using the indexed start offset at 12 kHz, and regenerates STFT and DWT with the existing GitHub extractor. The same Drive noisy signal is used for both feature types so that the noise realization is aligned with the supplied Envelope input. The supplied envelope frame arrays are trusted to be in their documented index order; their extraction algorithm is not independently regenerated by this script.

The Drive folders split windows chronologically within each recording. Both folders include all 40 recording groups, so their labels are not used for model selection or final testing. We instead combine them and use the original manifest: 0–1 HP train, 2 HP validation, 3 HP test. Clean/noisy versions of each window always belong to the same partition. The Drive summaries indicate 5,592 window pairs, distributed as 2,689 training, 1,449 validation and 1,454 testing pairs after regrouping.

## Run

From the repository root, with Python and TensorFlow installed:

```bash
python -m pip install -r requirements.txt
python -m src.train_hybrid --dataset data/raw/envelope --check-only
python -m src.train_hybrid --dataset data/raw/envelope --epochs 30 --baseline
```

If the source window check fails, investigate the Drive preprocessing or index rather than disabling the check or joining incompatible windows.

The CNN uses a 25 x 263 input (257 STFT bins + 6 DWT bands); the LSTM receives the 25 x 68 supplied Envelope frame sequence. Normalization is fitted on the training partition only. The two branches output 64-element vectors, which are concatenated and passed through Dense(64), dropout and four-class softmax. Class IDs remain normal=0, inner_race=1, ball=2, outer_race=3. Validation loss determines early stopping and learning-rate reduction. The optional baseline uses the existing CNN on the same windows, not previously reported scores on a different cohort.

Outputs under `models/hybrid/`:
- `stft_dwt_envelope_cnn_lstm.keras`
- `results.json`: training history, class order, group counts, window and recording accuracy, macro-F1, confusion matrices and individual recording predictions, separately for clean and noisy test windows.
- `stft_dwt_baseline.keras` when `--baseline` is used.

A complete local experiment was reported on 26 November 2026. See the [archived measured results](../reports/hybrid/2026-11-26/README.md) and [original trained-model artifacts](https://drive.google.com/drive/folders/1RCVT_pJwR7g_njQP1bRmwgwDp3ilPkZb). The test set is held out from model fitting and early stopping; report both window-level and recording-level performance. This experiment evaluates cross-load performance on CWRU, not deployment accuracy on arbitrary bearings.
